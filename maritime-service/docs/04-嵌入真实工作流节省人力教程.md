# 把它嵌入真实工作流节省人力教程

这一份不只是教你“怎么用”，而是教你“怎么真的省人”。

## 1. 先说结论

如果你想真正替代一部分人工劳动，不要一上来就追求“全自动无人值守”。

最稳的做法是：

1. 先做半自动
2. 再做自动拉数
3. 最后做自动归档和审批

## 2. 现在这套最适合替代哪部分人工

最适合替代的是：

- 找模板
- 复制粘贴合同字段
- 手工改表格行
- 手工改日期、运价、港口句子
- 手工另存为

这些动作的共同特点是：

- 重复
- 机械
- 容易出错
- 不值得人脑耗费注意力

## 3. 建议的真实落地顺序

### 第一阶段：人工填 Excel，系统出 Word

这是现在已经能做的。

工作流是：

1. 业务同事拿一份空白 Excel 模板
2. 把当前业务填进去
3. 拖到批处理文件
4. 生成 Word
5. 业务同事快速复核
6. 发出

这一步已经能节省大量“复制粘贴 + 改模板”的时间。

### 第二阶段：从真实业务表直接转入生成器

这一步要做的是：

- 你们原来业务表里某几行数据
- 自动转成这套输入格式

也就是说，以后可能不需要人工再手抄一次 Excel 模板。

### 第三阶段：加入审批和归档

这一步要做的是：

- 生成后自动放到固定目录
- 自动记录谁生成、何时生成
- 自动发给审核人

### 第四阶段：接 agent

等上面三步稳定后，agent 才有价值。

比如：

- agent 先读业务表
- 自动判断套哪个模板
- 自动生成 Excel 或 JSON
- 调用合同生成器
- 把结果发给人确认

## 4. 什么叫“真的省人”

不是让人完全离开流程，而是让人只做最值得做的那 10%。

例如以前一个人出一份合同可能要：

1. 找模板
2. 打开旧合同
3. 复制
4. 改字段
5. 改表格
6. 改日期
7. 检查格式
8. 保存

现在应该变成：

1. 填数据
2. 点生成
3. 看 30 秒
4. 发出

这就已经是非常实在的降本。

## 5. 我建议你在团队里怎么推广

### 第一步

先不要一下子说“以后都用这个”。

先选一个最熟练、最愿意配合的人，让他先用。

### 第二步

让他连续用 5 到 10 次。

记录：

- 哪些字段最容易填错
- 哪些模板最常用
- 哪些输出还需要调整

### 第三步

把这些反馈固化进：

- Excel 模板
- 教程
- 脚本默认值

### 第四步

再推广给第二个人。

## 6. 如果你以后要把它接到 agent

最好的接法不是“让 agent 直接操作 Word”。

最好的接法是：

1. agent 负责读业务数据
2. agent 负责整理成 JSON
3. agent 调用 `contract_workflow.py`
4. agent 输出 Word 和摘要
5. 人做最终确认

这样 agent 不需要直接碰复杂版式，只需要负责结构化和调度。

## 7. 未来接 req2 / req3 时怎么共用

req1、req2、req3 的共用能力其实已经浮现出来了：

- 读取 Excel
- 生成标准化中间数据
- 输出结果文件
- 保留日志

所以你现在不是在“只做一个出合同脚本”，而是在搭“航运业务自动化工作台”的第一块地基。
