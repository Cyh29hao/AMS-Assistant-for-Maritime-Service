﻿# 开发者维护说明

这份文档给未来维护这套 skill 的人看。

## 1. 代码入口

主入口：

- `scripts/contract_workflow.py`

配置入口：

- `scripts/contract_template_registry.json`

模板目录：

- `assets/contract_templates/`

示例请求：

- `examples/contract_requests/`

示例工作簿：

- `examples/workbooks/`

输出目录：

- `output/contracts/`
- `output/reports/`

## 2. 主脚本有哪些命令

### 生成全部示例

```bash
python scripts/contract_workflow.py build-examples
```

### 自检示例

```bash
python scripts/contract_workflow.py verify-examples
```

### 从 JSON 生成

```bash
python scripts/contract_workflow.py from-json --input examples/contract_requests/domestic-forwarder-mu-chuang-362.json
```

### 从 Excel 生成

```bash
python scripts/contract_workflow.py from-workbook --input examples/workbooks/domestic-forwarder-mu-chuang-362.xlsx
```

### 生成工作簿模板

```bash
python scripts/contract_workflow.py make-workbook-template --output examples/workbooks/blank-contract-template.xlsx
```

## 3. 你最需要理解的设计点

### 设计点 1：这是坐标型模板引擎

当前不是 mail merge，不是 docxtpl，也不是通用占位符渲染器。

当前逻辑是：

- 记录每种模板的关键段落坐标
- 把字段写到这些段落

所以一旦业务改模板，最先该检查的不是 Python，而是：

- `contract_template_registry.json`

### 设计点 2：为什么要保留 JSON 和 Excel 双入口

因为两者服务不同对象：

- Excel：给业务人员
- JSON：给脚本、agent、系统集成

不要轻易删掉任一入口。

### 设计点 3：为什么会生成 report JSON

这是为了：

- 可追踪
- 好排错
- 以后接审批流或数据库

## 4. 如果模板改了，你怎么修

### 第一步

先人工打开 Word 模板，看改的是：

- 只是正文文案改了
- 还是段落顺序改了
- 还是表格结构改了

### 第二步

用 `python-docx` 把模板段落号重新打印出来，定位关键内容。

### 第三步

更新：

- `scripts/contract_template_registry.json`

### 第四步

跑：

```bash
python scripts/contract_workflow.py verify-examples
```

### 第五步

人工打开 `output/contracts/` 看生成结果

## 5. 如果要增加一个新模板

按这个顺序做：

1. 把新 `.docx` 放进 `assets/contract_templates/`
2. 在 `contract_template_registry.json` 里新增一个 `template_key`
3. 配置段落索引
4. 如果有货物表，配置 `cargo_table_index` 和列映射
5. 写一个新的 JSON 示例
6. 跑 `build-examples`
7. 跑 `verify-examples`

## 6. 当前已知限制

### 限制 1

`freight_clause_cn` 的中文句子是按规则自动拼的，适合当前模板，但不一定覆盖所有未来业务句式。

### 限制 2

境内模板现在只在一个段落里写入船舶规范多行内容，没有完全复刻“每行单独一个段落”的高级排版。

### 限制 3

这套系统还没直接读“真实业务主表”的原始格式，目前读的是本工具自己的 Excel 模板。

## 7. 我建议未来的演进路线

### 路线 A：继续用坐标型模板，但做强工具化

适合：

- 模板结构几年内都不会大改
- 目标是尽快稳定产出

### 路线 B：逐步迁移到占位符模板

适合：

- 模板会经常变
- 想降低维护门槛

我建议先把路线 A 用顺，再规划路线 B。
