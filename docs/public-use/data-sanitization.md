# 数据脱敏说明

## 适用范围

这份说明适用于仓库中的：

- 示例 Excel
- 示例 JSON
- 演示用 Word 合同
- 原始需求邮件
- 网站查询结果示例
- 截图、日志、报告、演示视频

## 基本原则

对外公开、对外演示、对外打包、对外分享时，默认应优先使用脱敏数据，而不是直接使用真实业务数据。

## 建议脱敏的内容

### 个人与组织标识

- 邮箱地址
- 手机号
- 联系人姓名
- 员工编号
- 客户名称
- 供应商名称
- 内部团队名称

### 业务与交易标识

- 合同编号
- 提单号
- 报关单号
- 箱号
- 内部单号
- 客户订单号

### 金额与条款

- 运费单价
- 滞期费
- 银行账号
- 收款信息
- 报价区间
- 客户专属条款

### 系统与环境信息

- 登录态文件
- token
- refresh token
- cookie
- 本地机器用户名
- 内网路径
- 服务器地址

## 当前仓库中的特别提醒

### `our_requirements/`

这个目录当前仍保留了历史需求材料与原始样本输入。

如果仓库面向更广泛公开传播，建议把这里视为：

- 内部来源材料
- 历史参考材料
- 不应默认对外复用的原始输入

如果未来要做更干净的公共演示版，建议：

1. 将原始邮件替换为脱敏摘要
2. 将真实附件替换为纯示例文件
3. 将含真实业务痕迹的 Excel / Word 样本改为演示版

### 登录态与查询结果

`req2` 的网站自动化会在本地保存：

- 登录态
- 网站查询报告
- 更新后的工作簿

这些文件应当保留在本地用户目录或本地工作区，不应提交回 Git 仓库。

## 对外演示最推荐的做法

1. 用专门的演示账号
2. 用演示环境或已授权测试环境
3. 用已脱敏的 Excel / JSON / Word 示例
4. 屏蔽浏览器里的真实账号信息与历史记录

## 一句话版本

对外公开时，默认不要相信“示例文件看起来像样例就一定安全”；应把业务标识、账号信息、交易信息和登录态都当成潜在敏感数据处理。
