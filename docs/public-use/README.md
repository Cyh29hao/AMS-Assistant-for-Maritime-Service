# 对外公开使用说明

这组文档是给“准备把仓库公开给更多人看”的场景准备的。

当前这个仓库更接近：

- 内部业务自动化原型仓库
- 实施与落地仓库
- 需求整理、脚本实现、桌面化打包并行推进的工程仓库

它还不是一个“默认无限制开放使用”的通用开源产品仓库。

如果你准备继续公开传播、给客户试用、给同事下载、或者对外展示，建议先看这几份文件：

1. [LICENSE](../../LICENSE)
2. [data-sanitization.md](./data-sanitization.md)
3. [template-sources.md](./template-sources.md)
4. [automation-security-boundaries.md](./automation-security-boundaries.md)

## 这组说明解决什么问题

### 许可证

明确当前仓库默认按“保守公开、内部评估、非默认宽松开源”来处理。

### 数据脱敏

明确哪些数据可以作为示例公开，哪些应该在对外前做清洗。

### 模板来源

明确模板、样本、条款、版式和业务文件不是自动就能对外二次分发的。

### 自动化边界

明确账号、站点、网页登录、查询、回填这些动作只能在已授权场景下使用。

## 当前建议

如果你要把这个仓库继续往“公开给别人下载”的方向推进，建议顺序是：

1. 先用 release 形式给终端用户分发
2. 源码仓库主要面向维护者和评估者
3. 对外演示时优先使用脱敏数据和脱敏模板
4. 不把真实登录态、真实客户文件、真实回填结果提交进仓库
