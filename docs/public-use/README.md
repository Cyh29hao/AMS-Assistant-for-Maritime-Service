# 对外公开使用说明

这组文档是给“准备把仓库公开给更多人看”这个场景准备的。

当前这个仓库更接近：

- 内部业务自动化原型仓库
- 实施与落地仓库
- 需求整理、脚本实现、桌面化打包并行推进的工程仓库

它还不是一个默认无限制开放的通用开源产品仓库。

如果你准备继续公开传播、给客户试用、给同事下载，或者对外展示，建议先看这些文件：

1. [LICENSE](../../LICENSE)
2. [data-sanitization.md](./data-sanitization.md)
3. [template-sources.md](./template-sources.md)
4. [automation-security-boundaries.md](./automation-security-boundaries.md)
5. [public-private-split-plan.md](./public-private-split-plan.md)

## 这组说明解决什么问题

### 许可证

明确当前仓库默认按“保守公开、可评估、可内部试用”来处理，而不是默认宽松开源。

### 数据脱敏

明确哪些数据可以作为示例公开，哪些内容必须在公开前清洗或替换。

### 模板来源

明确模板、样本、条款、版式和业务文档不自动等于可对外再次分发。

### 自动化边界

明确账号、站点、网页登录、查询、回填这些动作只能在已授权场景下使用。

### 公开 / 私有拆分

明确“工具能力可以公开，但真实业务内容不应该直接公开”的推荐落地方式。

## 当前建议

如果你要把这个仓库继续往“公开给别人下载”的方向推进，推荐顺序是：

1. 优先通过 release 分发给终端用户
2. 源码仓库主要面向维护者和评估者
3. 对外演示时优先使用脱敏数据和脱敏模板
4. 不把真实登录态、真实客户文件、真实回填结果提交进公开仓库
