# 账号与站点自动化的安全边界说明

## 适用范围

这份说明主要针对：

- `req2` 的网页登录、登录态保存、单票查询、整表回填
- 未来可能接入的 `req3` 网站查询和报表生成

## 基本原则

本仓库中的自动化能力，只应当用于你已经获得明确授权的账号、网站、环境和数据。

## 允许的使用前提

使用前应至少满足这些条件：

1. 你对目标账号有合法访问权限
2. 你被允许对目标站点执行这类自动化操作
3. 你被允许读取并处理相关业务数据
4. 你理解自动化结果仍需要业务复核，而不是盲信

## 明确不建议的用法

### 不要做

- 用未授权账号运行自动化
- 绕过站点访问控制或登录保护
- 抓取你无权获取的数据
- 用脚本替代你不被允许替代的人工审批流程
- 将登录态、token、cookie 提交到 Git 仓库
- 将脚本用于压测、批量采集或站点滥用

## 当前实现中的实际边界

### req2 登录态

当前 `req2` 会在本地保存网站登录态与查询结果，用于后续复用。

这意味着：

- 这些文件是敏感文件
- 它们属于本地运行痕迹
- 它们应当保留在本地工作区或本地用户目录
- 它们不应进 Git 仓库、不应发给第三方

### 回填动作

`req2` 的整表自动回填会修改 Excel 输出结果。

这意味着：

- 自动化结果不应代替业务最终责任
- 特别是已通关、件数、重量等字段，仍应按业务要求抽样复核

## 公开 release 时应该怎么说

如果你把桌面版 release 给别人试用，建议明确说明：

1. 软件只适用于已授权的内部或测试场景
2. 使用者必须自行准备并管理合法账号
3. 发布方不提供任何绕过权限控制的能力
4. 站点规则变化、页面变化、接口变化可能导致功能失效

## 建议的操作习惯

1. 用专门的业务测试账号而不是个人主账号
2. 定期清理本地登录态和历史查询结果
3. 在共享电脑上避免长期保留登录态
4. 对自动回填结果保留人工复核环节

## 一句话版本

这个仓库提供的是“在授权场景内帮助你少做重复劳动”的自动化能力，不是“替你绕过权限和责任边界”的工具。
