## 1. 项目定位

Assistant for Maritime Service（简称 AMS）是一个面向航运业务同事使用的本地业务自动化工作台。

它的目标不是做开放式聊天机器人，而是把日常重复、易错、依赖人工复制粘贴的工作，收敛为几个可执行、可追踪、可导出的自动化流程。

当前聚焦 3 类高频业务：

1. 根据业务表格自动生成航次合同
2. 自动查询提单通关状态并回填业务表
3. 根据 LINE UP 和外部查询结果自动生成船期表

## 2. 项目目标

### 2.1 业务目标

1. 降低人工录入 Word、Excel、网页查询的重复劳动
2. 降低合同出错、漏填、抄错字段的风险
3. 提高每天固定查询类工作的稳定性和可追踪性
4. 让非技术同事可以通过网页界面完成自动化任务

### 2.2 产品目标

1. 提供一个简单明确的本地 HTML 网页入口
2. 让用户通过“上传文件 / 点击执行 / 下载结果”的方式完成任务
3. 保留任务日志、执行结果和失败原因
4. 支持后续扩展新的航运自动化流程

## 3. 目标用户

### 3.1 核心用户

1. 航运业务操作同事
2. 负责合同出具的同事
3. 负责船期整理和通关跟踪的同事

### 3.2 用户特征

1. 熟悉业务，但不一定熟悉软件系统
2. 更习惯 Excel、Word、网页录入，而不是复杂后台系统
3. 对“是否出结果”和“结果是否准确”比功能花哨更敏感

## 4. 使用场景

### 场景 A：出合同

业务同事拿到一份业务表格后，希望选中某票或某几票业务，系统自动套用正确的合同模板，补齐可变字段，并导出 Word 合同。

### 场景 B：查通关

业务同事每天需要检查未通关提单号是否已放行。如果已放行，则将件数、毛重等信息写回业务表。

### 场景 C：做船期表

业务同事拿到 LINE UP 表，希望系统自动提取船名并查询网站，再整理成“港口 x 区域”的矩阵型船期表。

## 6. 功能需求

## 6.1 功能一：合同自动生成

### 6.1.1 功能目标

从业务表格中读取指定业务行，自动选择合同模板，填充变量内容，导出 `.docx` 合同。

### 6.1.2 输入

1. 一份业务表格
2. 用户选择的目标行，或系统按规则识别的目标业务
3. 合同模板

### 6.1.3 输出

1. 生成后的 Word 合同
2. 生成日志
3. 字段映射记录

### 6.1.4 关键业务规则

1. 系统需要先判断应使用哪份模板
2. 模板中的红字区域视为待填变量
3. 允许一票业务对应多条货物明细
4. 允许一份合同包含多条装港/卸港/货量/货名信息
5. 合同生成后要保留原始版式，不破坏样本样式

### 6.1.5 已识别主要字段

1. 合同编号
2. 日期
3. 船名
4. 租家名称
5. 船东名称
6. 货物总量
7. 货物描述
8. 货物明细列表
9. 装港
10. 卸港
11. laycan
12. 装卸条款
13. 滞期费/速遣费
14. 运费条款
15. 银行信息

### 6.1.6 页面动作

1. 上传业务表格
2. 预览可识别的业务记录
3. 选择要生成的合同记录
4. 查看系统判断出的模板
5. 手动修改少数字段
6. 点击生成合同
7. 下载结果

### 6.1.7 异常处理

1. 模板识别失败时，允许用户手动指定模板
2. 必填字段缺失时，阻止生成并提示缺失项
3. 多条明细无法映射时，提示用户检查表格格式

## 6.2 功能二：通关状态查询并回填

### 6.2.1 功能目标

自动登录目标网站，查询未通关提单状态，若已放行则自动更新业务表。

### 6.2.2 输入

1. 一份业务表
2. 表中至少包含提单号、当前备货状态
3. 网站登录配置

### 6.2.3 输出

1. 更新后的业务表
2. 查询日志
3. 失败记录

### 6.2.4 标准流程

1. 从业务表筛出“未通关”记录
2. 登录目标网站
3. 逐票查询提单号
4. 判断是否为“已放行”
5. 如已放行，回填：
   - 备货状态 = 已通关
   - PCS
   - MT
6. 保存并导出更新后的结果

### 6.2.5 页面动作

1. 上传待回填表格
2. 配置查询范围
3. 立即执行查询
4. 查看查询进度
5. 下载更新结果
6. 查看失败明细

### 6.2.6 定时任务

1. 支持每天 17:00 自动执行
2. 支持启用/停用定时任务
3. 支持查看最近执行日志

### 6.2.7 主要风险

1. 网站可能有验证码或登录限制
2. 页面结构可能改版
3. 一票多结果时需要额外判定规则
4. 回填目标格式可能并不总是统一

## 6.3 功能三：船期表生成

### 6.3.1 功能目标

读取 LINE UP 文件中的船名，逐条查询网站，并按港口与区域生成矩阵型船期表。

### 6.3.2 输入

1. LINE UP Excel 文件
2. 网站查询配置
3. 输出模板

### 6.3.3 输出

1. 一张船期矩阵表
2. 查询日志
3. 未匹配记录

### 6.3.4 当前可确认的输入特征

LINE UP 样本已包含：

1. 预靠码头
2. 中文船名
3. 英文船名
4. 进口航次
5. 出口航次
6. 船长
7. 状态
8. 计划抵锚地时间
9. 靠泊时间
10. 离泊时间
11. 船代

### 6.3.5 当前目标输出形态

1. 行表示目的港
2. 列表示区域，例如九区、十区、罗泾
3. 单元格填入命中的船名和业务简称
4. 当前可先只支持九区和十区

### 6.3.6 页面动作

1. 上传 LINE UP 文件
2. 预览识别出的船名
3. 选择区域范围
4. 点击开始查询
5. 预览生成结果
6. 下载 Excel

### 6.3.7 风险与不确定项

1. 网站查询结果中哪个字段决定分区尚不完全明确
2. 同一港口命中多条船时展示规则未最终确定
3. 船名匹配可能需要中英文兼容和模糊匹配

## 7. 通用能力需求

### 7.1 文件管理

1. 支持上传 Excel、Word 模板
2. 支持下载处理结果
3. 保留原始文件名和生成时间

### 7.2 任务管理

1. 显示任务状态：未开始、执行中、成功、失败
2. 提供任务开始时间、结束时间、耗时
3. 支持查看失败原因

### 7.3 日志与可追踪性

1. 每次执行要记录输入文件、输出文件、结果摘要
2. 每条失败记录要保留具体原因
3. 外部网站自动化要保留步骤日志

### 7.4 手动修正能力

1. 自动识别失败时允许用户手动补录
2. 合同生成前允许用户修改少数字段
3. 船期结果导出前允许人工确认

## 8. 非功能需求

### 8.1 易用性

1. 页面尽量少字段、少跳转
2. 核心动作控制在 3 步以内
3. 结果页明确显示“成功多少、失败多少”

### 8.2 性能

1. 合同生成单次操作应在秒级完成
2. 查询型任务允许分钟级完成，但要显示进度

### 8.3 稳定性

1. 自动化失败不能导致程序整体崩溃
2. 单条记录失败不影响其他记录继续执行

### 8.4 安全性

1. 网站账号信息本地保存
2. 不把业务文件自动上传到外部云端
3. 敏感结果文件仅保存在本机目录

## 9. MVP 建议

### MVP 阶段一

合同自动生成

原因：

1. 输入输出最明确
2. 不依赖网页登录
3. 最容易快速产出可见成果

### MVP 阶段二

船期表生成

原因：

1. 已有真实 Excel 样本
2. 输出形式相对固定
3. 风险主要集中在网页自动化

### MVP 阶段三

通关状态回填

原因：

1. 依赖定时任务和网页登录稳定性
2. 业务判断分支更多
3. 需要更完善的失败处理

## 10. 验收标准

### 10.1 合同功能验收

1. 能正确识别并套用模板
2. 生成的 Word 版式与样本基本一致
3. 关键字段无漏填、错填

### 10.2 通关功能验收

1. 能成功登录网站并执行查询
2. 对“已放行”记录正确回填
3. 查询失败有日志可查

### 10.3 船期功能验收

1. 能正确读取 LINE UP 文件
2. 能成功查询并生成矩阵表
3. 未匹配船名有单独清单

## 11. 当前待确认事项

1. 合同输入表格的真实样本
2. 模板选择规则
3. 合同编号生成规则
4. 红字字段的完整清单
5. 通关回填表格的真实样本
6. 网站账号、登录流程、是否有验证码
7. 船期表最终输出模板
8. 船名匹配规则是精确、模糊还是人工确认

## 12. 结论

AMS 更适合作为一个“本地网页 + Python 后端”的业务自动化工具，而不是一个纯聊天产品。

它的第一价值在于替代人工整理、查询、填表和出文档的过程；AI 能力后续可以加，但不应该先于流程自动化本身。
