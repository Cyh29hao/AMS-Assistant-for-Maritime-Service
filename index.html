FUNCTIONS

AMS 当前规划的三个核心模块

每个模块都对应一个明确的业务结果，方便快速理解，不做泛化表述。

Module A

合同中心

从业务表格自动生成 Word 合同，减少手工改模板、补红字和复制粘贴的步骤。

  • 当前仓库已经可直接运行
  • 输入输出最明确
  • 适合最先落地
  • 不依赖网页登录

Module B

通关查询

查询未通关提单状态，如已放行则自动回填备货状态、PCS 和 MT 等关键数据。

  • 适合后续接定时任务
  • 对登录稳定性要求高
  • 失败日志必须清楚

Module C

船期汇总

读取 LINE UP 船名后查询网站，生成“港口 x 区域”的矩阵型船期表。

  • 已有真实 Excel 样本
  • 输出结构容易标准化
  • 适合第二阶段实现

FAQ

常见问题解答

这个页面本身能直接出合同吗？

还不能。它现在是入口页和说明页。真正的合同生成、网页登录查询和 Excel 回填，会接到后续本地网页工具里。

普通使用者需要了解 GitHub 吗？

不需要。理想使用方式是直接打开这个页面，再从页面进入后续的本地工具。

为什么不直接做成纯在线系统？

因为业务里涉及 Word、Excel、网页登录和敏感数据，纯在线静态页不够稳，也不适合长期维护。

DEPLOYMENT

部署方式

这一部分面向需要复制页面、维护页面或继续接本地工具的人，因此信息会更详细一些。

Option 1

直接访问在线入口页

最轻量的方式，适合统一对外说明 AMS 的功能、边界和后续入口。

  • 适合所有人访问
  • 适合作为项目首页
  • 不需要本地安装
Option 2

自己部署 GitHub Pages

适合希望快速复制一个相同入口页的人。只要会用 GitHub，就能几分钟部署出来。

git init
git branch -M main
git add .
git commit -m "Deploy AMS site"
git remote add origin YOUR_REPO_URL
git push -u origin main
Option 3

后续接本地网页工具

真正涉及 Word、Excel、网页登录自动化的能力，建议用本地运行方式接入。

  • 业务文件不需要上传公网
  • 账号和日志留在本机
  • 更适合重复日常操作
