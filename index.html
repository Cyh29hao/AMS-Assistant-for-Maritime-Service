FUNCTIONS

AMS 不是泛用聊天页，而是三类明确业务动作。

每个模块都围绕一个结果展开：要么导出合同，要么回填表格，要么生成报表。

Module A

合同中心

读取业务表格，自动判断模板，补齐关键字段，输出结构完整的双语航次合同。

  • 适合优先做 MVP
  • 输入输出最明确
  • 不依赖网页登录

Module B

通关查询

登录目标网站查询提单状态，如已放行则自动回填业务表中的备货、PCS 和 MT。

  • 适合后续接定时任务
  • 对登录稳定性要求高
  • 失败日志必须清楚

Module C

船期汇总

读取 LINE UP 船名，查询外部结果后生成“港口 x 区域”的矩阵型船期表。

  • 适合第二阶段实现
  • 已有真实 Excel 样本
  • 输出形式容易标准化

APPROACH

为什么首页能放在 GitHub Pages，但核心能力放在本地运行。

GitHub Pages 适合做什么

  • 项目首页与功能介绍
  • 面向同事的操作说明
  • 后续的工具下载入口
  • 轻量级前端展示页面

为什么不把全部自动化都放到纯网页里

  • Word 合同模板处理不适合纯前端长期维护
  • 网页登录查询涉及稳定性、跨域和账号安全
  • Excel 回填与定时任务更适合本地服务执行
  • 业务数据本地保存，对家人和同事更安心

ROADMAP

建议推进顺序

先做最清晰、最容易形成可见成果的模块，再处理更重的网页登录自动化。

Phase 1

合同自动生成

先跑通表格到 Word 的完整链路，建立大家对 AMS 的信心。

Phase 2

船期汇总

把已有的 LINE UP 样本转成固定输出格式，积累查询逻辑。

Phase 3

通关回填

最后接入定时任务、网页登录和更完整的错误处理。
